# AI パイプライン（自己対戦データ → V → 対戦評価）

V（1手先読みの価値関数）の学習・評価の流れと、列スキーマの契約。数値はすべて実測。

## 流れ

```
collect-decisions.ts   → runN.jsonl + runN.schema.json   （自己対戦ログ、1行=1意思決定）
export_trees.py        → value-trees*.json + parity-check.json （LightGBM → 木のJSON）
src/ai/value-trees.json                              （採用した木をコミット）
value-ab.ts / eval-pool.ts                           （対戦での強さを測る）
```

- 収集 seed: 101–200（`splitSeeds('train')`）。報告 seed: 3001–3200（`splitSeeds('report')`）。重ねない。
- 学習データは方策を混ぜる（`seed % 4` で baseline / maximin / baseline-eps / random）。
  baseline だけだと V が「ベースラインの線」の上でしか校正されない。
- 引き分けは `label: null` で学習から除外する。評価では 0.5 勝として数える（不一致は既知）。

`features[name] ?? 0` が黙って 0 を埋めていた。例外は出ず、対戦の強さだけが 2pt 落ちた。

## 現行 V の状態（2026-10-25）

コミット済みの V は run3 学習版（29列の木）。凍結ベースラインv1 相手・report seed 3001–3200・4,400試合:

| V（学習データ／maximin の入力） | margin 0.05 | margin 0 | 引き分け |
|---|---|---|---|
| run3 学習（現行）・weather 0固定 | 82.4% [81.2, 83.5] | 83.1% [82.0, 84.2] | 6.3% / 5.2% |
| run3 学習（現行）・weather 実値 | 82.5% [81.3, 83.6] | 82.6% [81.5, 83.7] | 6.3% / 5.2% |
| run4 学習（weather 0固定の maximin） | 80.4% | 74.1% | 8.8% / 9.5% |
| run6 学習（weather 実値の maximin） | 81.5% [80.3, 82.6] | 77.5% [76.3, 78.7] | 8.1% / 7.3% |

- 現行 V は weather を 0 固定にしても実値でも強さが変わらない。
- 新しいデータで学習した V は「weather を直す」だけでは現行に届かない（run4 → run6 で +1.1/+3.4pt、
  それでも現行比 −1.0/−5.1pt）。margin0 と 0.05 の差は現行 0.1pt に対し run6 4.0pt で、
  **兄弟手の順位付け（ΔV）がまだ弱い**。原因はデータの質（H2: ラベルが混合方策の価値）側に残っている。

## 兄弟手の診断（`scripts/rollout-diagnostic.ts`）

V が「ベースラインと違う手」を選んだ決定点で、両方の手から同じ乱数列で R 本ずつ最後まで打ち、
勝率の差（ΔQ̂）と V の差（ΔV）を突き合わせる。共通乱数なので同じ seed のペアは同じ乱数を共有する。

```bash
npx tsx scripts/rollout-diagnostic.ts --points=3000 --rollouts=32 --builds=6 --seeds=120 --mode=maximin --margin=0
# 出力: ~/.local/state/pokemon-champions/rollout-<tag>.jsonl（1行 = 1決定点）
```

出す指標: P(ΔQ̂>0)、平均 ΔQ̂、平均 regret、Spearman(ΔV, ΔQ̂)、ΔV のビンごとの ΔQ̂（校正曲線）、
行動クラス別（攻撃技／変化技／交代）の ΔQ̂。

### 2026-10-25 の結果（現行 V、3,000点、rollout 32本、mode=maximin(=worst)、margin 0）

| 指標 | 値 |
|---|---|
| V の手が上回った / 同等 / 下回った | 24.4% / 44.6% / 31.0% |
| 平均 ΔQ̂ | **−4.05pt** [−5.04, −3.07]（符号検定 p<1e-4） |
| 平均 regret | 9.39pt |
| Spearman(ΔV, ΔQ̂) | **−0.020**（順位情報が無い） |
| ΔV 5–10pt / 10–20pt の ΔQ̂ | −13.3pt / −12.5pt |
| ΔV > 20pt の ΔQ̂ | +11.6pt（11%の点でだけ正しい） |
| 交代 / 変化技 / 攻撃技 | −11.9pt / −13.7pt / +2.6pt |

- デプロイの `trustMargin 0.05` が採用する領域（ΔV≥5pt、全体の49%）は平均 −7.4pt。
  **margin は「差が小さい手を捨てる」だけで、中帯域の ΔV は当てにならない。**
- ただしこの診断の継続方策は「両者ベースラインv1」なので、**仕込みの手（設置・交代・変化技）は
  構造的に不利**に出る。trajectory 全体の強さ（v1 相手に 79–83%）とは別物として読む。
- 対照実験: `--margin=10`（常にベースラインに委譲）で 49.9% [48.5, 51.4]（ミラーなので期待どおり）。
  ハーネス側の偏りではないことを確認済み。

### 継続方策を V にした診断（`--continuation=value`、300点、rollout 16本、mode=maximin、margin 0）

2ターン目以降を「自分側 V・相手側 v1」（実戦と同じ構図）で打つ。決定点の選び方は継続方策に依存しないので、
`--continuation=v1` と同じ 300点を対応づけて比べられる（CI は bootstrap 95%）。

| 指標 | continuation=value | continuation=v1（同じ300点） |
|---|---|---|
| 平均 ΔQ̂ | **+21.56pt** [+17.50, +25.61] | +1.86pt [−1.59, +5.48] |
| Q̂(Vの手) / Q̂(v1の手) | 67.1% / 45.5% | 47.0% / 45.1% |
| 上回り / 同等 / 下回り | 48.3% / 42.7% / 9.0% | 24.0% / 40.0% / 36.0% |
| 平均 regret | 1.56pt | 8.22pt |
| Spearman(ΔV, ΔQ̂) | **+0.252** | +0.183 |
| ΔV 5–10 / 10–20 / >20pt | +21.6 / +39.2 / +28.7pt | −9.3 / +9.8 / +16.1pt |
| 交代 / 変化技 / 攻撃技 | +23.1 / +12.5 / +24.8pt | −11.8 / −4.3 / +10.4pt |
| ΔV≥5pt（margin 0.05 の採用域、209点） | +28.4pt [+23.5, +33.2] | +3.4pt [−1.1, +8.0] |

- **v1 継続での負けは「仕込みの手を v1 が引き継げない」ことによるもの**だった。V 自身が打ち継げば、
  交代・変化技を含むすべてのクラスで V の手が上回り、ΔV にも順位情報がある（ΔV が大きいほど ΔQ̂ が大きい）。
- 未解明: V 継続の利得は V の手のあとでは +20.1pt あるのに、v1 の手のあとでは +0.4pt しかない（67.1−47.0 と 45.5−45.1）。
  V が v1 の手のあとの局面を立て直せていない（学習分布の外の可能性）。ハーネスの偏りは確認できなかった
  （エージェントは打ち継ぎの間に状態を持たず、`fork()` は乱数の状態を独立に複製する）。
- 所要時間: value 継続は 300点×16本で約5分（v1 継続は7秒）。

### 2手目の診断（`--second-step`、同じ300点、rollout 16本、continuation=value）

各診断点で V の手／v1 の手を1ターン打った後の局面で、もう一度 V の最善手と v1 の手を共通乱数で打ち比べる
（続きは V）。CI は診断点単位のクラスタ bootstrap 95%。所要約12分。

| 1手目 | 手が割れた | 割れた所の ΔQ̂（2手目） | Spearman(ΔV, ΔQ̂) | V 予測 → 実績（偏り） | Brier |
|---|---|---|---|---|---|
| V の手の後（3,586標本） | 71.6% | **+13.67pt** [+9.20, +18.43] | +0.318 | 55.2% → 67.8%（+12.54pt） | 0.150 |
| v1 の手の後（4,555標本） | 88.1% | **−16.74pt** [−20.28, −12.87] | +0.072 | 51.8% → 48.4%（−3.40pt） | 0.137 |

- **v1 の手の後では、V の2手目は v1 の2手目より 16.7pt 悪い。** v1 の1手目が交代なら −22.5pt、技なら −14.2pt。
  V の手の後では逆に V の2手目が 13.7pt 良い。**手の価値は「同じ方策が続けて打つ」ことで出ている**
  （計画の一貫性）。V は v1 が始めた計画を引き継げず、順位情報もほぼ無くなる（Spearman 0.07）。
- 局面価値の較正は「分布の外」で崩れていない（Brier は v1 の手の後のほうがむしろ小さい）。
  崩れているのは**兄弟手の順位付け**のほう。V の手の後では V が勝率を 12.5pt 過小評価している。
- 前節の未解明点（V 継続の利得が v1 の手の後では +0.4pt）はこれで説明がつく。V が打ち継ぐと、
  v1 の計画が途中で切り替わって損をする分と、V の強さの分が相殺している。
- 学習ラベルへの含意（H2）: 方策が混ざった軌跡では、ある手のラベルにその後の別方策の手の価値が乗り、
  さらに「計画の切り替え」の損失も乗る。V の兄弟手の順位付けが新しいデータで弱くなる理由の候補。
- 注意: 標本は決着・強制交代の局面を除いているので、V の手の後のほうが標本が少ない（V の手で決着が早まる）。

## 2026-10-25 に見つけて直した測定系のバグ

- **`--mode=maximin` が黙って `uniform` になっていた。** `ValueSearchOptions` の型に `'maximin'` が無く、
  CLI の cast で型検査を迂回していたため、`evaluate()` の「'worst' 以外は平均」の分岐に落ちていた。
  現在は `'maximin'` を `'worst'` の別名として受理し、未知の値は `value-ab.ts` が停止する。
- **`fork()` が情報レベルを引き継がず、`partial` の対戦でも探索が `full` になっていた。**
  1手先読みが相手の伏せ情報（未公開の技・持ち物）を見ていた。`fork()` は `this.information` を渡す。
  修正後の実測（現行 V、v1 相手、4,400試合）:

  | 相手モデル | margin 0.05 | margin 0 |
  |---|---|---|
  | uniform | 83.7% [82.6, 84.8] | 82.6% [81.5, 83.7] |
  | maximin(=worst) | 79.4% [78.2, 80.6] | 79.0% [77.8, 80.2] |

  参考: 修正前（full 情報の fork、`--mode=maximin` が uniform 扱い）は 82.5% / 82.6%。
  `collect-decisions.ts` の maximin は既定の `'worst'` で動いていたので、
  **学習データの専門家と評価していた専門家が別物だった**（この不一致は解消済み）。


## V を昇格させるときの手順

1. `npx jest` が緑（現行 V のまま）であることを確認。
2. `~/data/pokemon-decisions/value-trees-vN.json` を `src/ai/value-trees.json` にコピー。
3. **`parity-check.json` を `tests/fixtures/value-parity.json` にコピーする**（学習時の 200行サンプル）。
   忘れると `tests/value-trees.test.ts` が旧い列数で落ちる（＝昇格の検出になる）。
4. `value-ab.ts --split=report` を margin 0.05 / 0 の2本。昇格条件は「v1 相手に現行を下回らない」
   「（可能なら）現行 V との直接対戦で 50% 以上」。log-loss は補助指標。
