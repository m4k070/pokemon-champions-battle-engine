## 2. 捨てた案

- **特徴量の数を減らす**: run4 で旧28列に絞って学習 → 79.6%（77列と CI が重なる）。原因ではない。

- **run3 と run4 の単純結合で学習**: run3 に `weather` 列があり run4 に無いため、列の有無が
  データセット識別子として漏れる。やるなら列を揃えてから。
- **評価 seed のリーク**: 確認済みで無し（学習101–200 / 報告3001–3200）。

## 4. Opus の見立て（要点）

保存先: `~/logs/consult/opus-v4-regression.md`（moon にもコピー済み）

- 手がかりは **margin 0 と 0.05 の差**（run3版 0.1pt / run4版 6.3pt）。局面の価値は当たっているが、
  兄弟手の ΔV にノイズか偏りが乗っている。log-loss と AUC は局面間の差でほぼ決まるため、これを映さない。
- 仮説の優先順: H1 劣化した maximin の軌跡（最有力）> H2 ラベルが混合方策の価値になっている
  > H3 引き分け・PP 周りの分布変化 > H4 データ量不足。H0 として学習乱数だけで 2pt は動く。
- 診断の最優先は「共通乱数を使ったペア rollout」。V がベースラインと違う手を選んだ決定点を約2,000個、
  各候補手から同じ乱数で32本ずつ打ち、`P(Q̂(Vの手) > Q̂(ベースラインの手))`、平均 regret、
  ΔV と ΔQ̂ の Spearman、校正曲線を出す。行動クラス別に margin を決められる。
- 収集の改善順: Step 0 特徴量スキーマのガード（列が無ければ0をやめ、ハッシュ不一致でエラー）
  → Step 1 run5（maximin に正しい29列の run3 V を使う）→ Step 2 run3+run5 混合
  → Step 3 順位付けに効くデータ（分岐＋共通乱数、1手だけ逸脱、引き分け0.5、TD(λ)）。
- V の昇格条件: (a) v1 相手に2,200試合で現行を下回らない (b) 現行Vとの直接対戦で50%以上
  (c) ペア精度が落ちていない。log-loss は補助指標に留める。
- 推奨順: 安価な確認（3学習seedのばらつき・引き分けラベル）→ margin スイープ → Step 0 → run5 収集 → 合間に A 実装。
